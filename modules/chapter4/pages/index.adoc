== The Evaluation Challenge

In production AI, "Good" is subjective. We need to make it objective.
A comprehensive evaluation strategy must decouple the **Model** from the **Serving Infrastructure**.

* **TrustyAI** measures the _Model's_ intelligence (Accuracy).
* **GuideLLM** measures the _Infrastructure's_ capacity (Performance).
* **Custom Probes** measure the _Business_ alignment (Domain).

This lab provides a command-line workflow to run these disparate tests and aggregate the results into a single "Report Card" stored in S3.

== The 3-Dimensional Framework

We evaluate models against three distinct pillars. If a model fails any one of these, it is not production-ready.

[cols="1,3,1"]
|===
| Dimension | Business Question | Tool

| **1. Accuracy**
| *"Does the model know the answers?"*
Verifying multi-language capabilities and reasoning skills against standard benchmarks (MMLU, ARC).
| **Red Hat TrustyAI** (LMEval)

| **2. Performance**
| *"Can the model handle the traffic?"*
Stress-testing the infrastructure to find the breaking point (Max Throughput) and User Experience (Time-to-First-Token).
| **GuideLLM**

| **3. Domain**
| *"Does the model understand OUR business?"*
Testing the model against your specific industry terminology, compliance rules, and safety standards.
| **Custom Probes**
|===

== Course Structure

We have organized the audit into four modular phases.

=== Module 1: The Accuracy Exam (TrustyAI)
You will deploy a Kubernetes `LMEvalJob` to run standardized benchmarks against your model.
* **Goal:** Verify the model outperforms the baseline in English and Spanish reasoning.

=== Module 2: The Stress Test (GuideLLM)
Accuracy means nothing if the user waits 10 seconds for a token. You will use **GuideLLM** to hammer the endpoint with simulated traffic.
* **Goal:** Determine the maximum `Requests Per Second` (RPS) your hardware can sustain before latency spikes.

=== Module 3: The Specialist Interview (Domain)
Generic benchmarks don't test your business data. You will inject a custom "Exam Paper" specific to your domain.
* **Goal:** Verify the model handles industry-specific jargon and safety constraints.

=== Module 4: The Report Card (Visualization)
Raw JSON data in S3 is hard to read. You will visualize the results to create a stakeholder-ready report.
* **Goal:** Generate a "Pass/Fail" dashboard for the executive team.
